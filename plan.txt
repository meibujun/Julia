I. Complete Software Architecture and Module Organization
A. Overarching Design Philosophy and Principles
GenomicPro.jl embodies a layered modular architecture that achieves separation of concerns through distinct packages with clearly defined interfaces and responsibilities. The foundation rests on abstract type hierarchies leveraging Julia's multiple dispatch for zero-cost polymorphism and extensibility, allowing new methods to integrate seamlessly without modifying core code. Type-driven design ensures compile-time optimization and type stability across the entire codebase, while composable components enable users to construct custom analysis pipelines from modular building blocks. The architecture explicitly avoids anti-patterns that plague existing software—no god objects with excessive responsibilities, no misc.jl files becoming code dumping grounds, and no implicit dependencies creating brittle coupling.
Every design decision prioritizes three core objectives: performance approaching theoretical hardware limits through GPU acceleration and optimized numerical algorithms, extensibility enabling researchers to add novel methods without architectural refactoring, and maintainability through comprehensive documentation, extensive testing, and adherence to established Julia community style guides. The software treats quantitative genetics theory as foundational rather than optional, ensuring that every computational method maps to well-understood genetic principles and that results remain interpretable for breeding decisions.

II. Core Algorithms with Implementation Details and Computational Complexity
A. Traditional Genomic Prediction Methods
GBLUP (Genomic Best Linear Unbiased Prediction) forms the foundation for genomic selection. The mathematical model solves the mixed model equation y = Xβ + Zu + e where y represents phenotypes, β are fixed effects, u are random breeding values with u ~ N(0, Gσ²_u), and G is the genomic relationship matrix. The computational implementation constructs G using G = ZZ' / (2Σp_i(1-p_i)) where Z is the centered and scaled genotype matrix with entries coded as 0, 1, or 2 for allele counts, centered by subtracting 2p_i where p_i is the allele frequency, and scaled by dividing by √(2p_i(1-p_i)).
For direct solution with matrix inversion, the system constructs C = [X'X, X'Z; Z'X, Z'Z + G^(-1)λ] where λ equals the variance ratio σ²_e/σ²_u, solves Cs = [X'y; Z'y] through Cholesky decomposition when C is positive definite, and extracts breeding values u from the solution vector. Computational complexity reaches O(n³) for direct inversion with n individuals making it prohibitive beyond 10,000 animals, while memory requirements span O(n²) for storing G and C matrices.
The iterative solution through preconditioned conjugate gradient dramatically improves scalability. The algorithm initializes breeding values u to zero, computes the residual r as y minus current predictions, applies the preconditioner M typically the diagonal of the coefficient matrix, updates the search direction p using the preconditioned residual, computes the step size α through matrix-vector products avoiding explicit matrix inversion, updates breeding values adding α times p, checks convergence when the residual norm falls below tolerance typically 1e-6, and repeats until convergence. Computational complexity reduces to O(n²k) where k represents iterations typically 100-500, while memory requirements drop to O(n) enabling solution for 100,000+ animals.
GPU acceleration provides transformative speedups. The implementation transfers data matrices and relationship matrix G to GPU memory, implements matrix-vector products as CUDA kernels avoiding host-device transfers, performs vector operations including dot products and norms entirely on GPU, uses cuSPARSE for sparse matrix operations when G has sparsity, applies mixed precision with Float32 operations and Float64 accumulation balancing speed and accuracy, and achieves 50-200× speedup over CPU implementations.
Single-Step GBLUP (SSGBLUP) combines pedigree and genomic information through the unified relationship matrix H = [A₁₁ + A₁₂A₂₂⁻¹(G - A₂₂)A₂₂⁻¹A₂₁, A₁₂A₂₂⁻¹G; GA₂₂⁻¹A₂₁, G] where A represents the numerator relationship matrix from pedigree, subscript 1 denotes non-genotyped animals, subscript 2 denotes genotyped animals, and G is the genomic relationship matrix for genotyped animals. The practical implementation avoids explicitly constructing H through careful matrix operations.
The algorithm computes A₂₂ as the pedigree-based relationship matrix for genotyped animals only, forms the difference matrix D = G - A₂₂ quantifying the discrepancy between genomic and pedigree relationships, constructs the inverse relationship matrix H^(-1) using the decomposition avoiding explicit inversion of large matrices, and solves mixed model equations with H^(-1) through iterative methods. Computational complexity reaches O(n²_g + n_gn_p) where n_g represents genotyped animals and n_p total pedigreed animals, substantially lower than O((n_g+n_p)³) for direct methods.
Memory optimization techniques include storing only the upper triangle of symmetric matrices, using sparse representations for A when pedigrees are large but connections are sparse, computing A₂₂⁻¹ through Cholesky decomposition and sparse back-substitution, and streaming A₁₂ blocks to avoid loading the full pedigree-genomic cross-product.
ssGWABLUP (Single-Step GWAS-BLUP) enhances SSGBLUP by incorporating prior GWAS information. The method first runs a preliminary GWAS identifying putative QTLs through marker-by-marker association testing, calculates posterior probabilities PP_j for each SNP being causal using PP_j = (LR_j × π₀) / (LR_j × π₀ + (1-π₀)) where LR_j is the likelihood ratio and π₀ is the prior probability of causality, computes weights w_j based on posterior probabilities emphasizing regions with strong prior evidence, constructs the weighted genomic relationship matrix G_weighted = ZWZ' / tr(ZWZ') where W is a diagonal matrix of weights, forms the H matrix using G_weighted instead of uniform-weight G, and solves the single-step mixed model equations.
The implementation details include efficient sparse matrix multiplication for ZWZ' when markers are numerous, adaptive weight calculation with regularization preventing extreme weight concentration, integration with ssGBLUP code through modular G matrix construction, and validation comparing predictions against uniform-weight ssGBLUP. Performance benchmarks demonstrate 5-15% accuracy improvement over standard ssGBLUP with minimal computational overhead under 20% additional time for large datasets.
B. Bayesian Methods with MCMC Implementation
BayesR and BayesRC implement sophisticated Bayesian variable selection with BayesRC incorporating functional genomic annotations. The statistical model assumes marker effects follow a mixture of normal distributions β_j ~ Σ_k π_k N(0, σ²_k) where k indexes mixture components typically including zero effect, small effect (0.01% of genetic variance), moderate effect (0.1%), and large effect (1%), and mixing proportions π_k follow a Dirichlet prior.
BayesRC extends this model by making mixing proportions depend on functional annotations through logit(π_jk) = μ_k + Σ_l α_lk × annotation_jl where annotation_jl represents the l-th annotation for marker j and α_lk quantifies how annotation l influences component k membership. The Gibbs sampling algorithm cycles through marker effects sampling each β_j conditional on current residuals and mixture assignment, sampling mixture component memberships for each marker based on current effect size and annotation-influenced probabilities, updating variance components through inverse-gamma distributions with shape and scale parameters updated from current effects, sampling annotation effect parameters α through Metropolis-Hastings proposals with acceptance probability balancing likelihood improvement and prior compatibility, and updating mixing proportion base levels μ through Dirichlet-multinomial conjugacy.
The implementation optimizes computational efficiency through pre-computing X'X and X'y avoiding repeated calculations, updating residuals incrementally as r = r + X_j(β_j^old - β_j^new) rather than recomputing from scratch, using conjugate updates wherever possible eliminating Metropolis-Hastings overhead for variance components, sampling mixing components with vectorized operations across all markers simultaneously, storing only posterior samples at thinning intervals reducing memory requirements, implementing convergence diagnostics including Gelman-Rubin statistics on multiple chains, and providing trace plots for monitoring chain mixing and identifying burn-in periods.
Computational complexity spans O(T×n×m) where T represents MCMC iterations typically 50,000, n is sample size, and m is marker count, with primary bottleneck being the residual update step repeated millions of times. GPU acceleration targets the residual update kernel achieving 10-50× speedup, batch processing marker effects in groups of 1,000-10,000 reducing kernel launch overhead, using mixed precision with BFloat16 forward operations and Float32 accumulation maintaining accuracy, and streaming marker data when the full genotype matrix exceeds GPU memory.
BayesA, BayesB, BayesC, and BayesCπ represent special cases or simplifications of the BayesR framework. BayesA assumes all markers have non-zero effects with marker-specific variances following scaled inverse chi-square distributions σ²_j ~ χ⁻²(ν, S) where ν controls the heaviness of tails and S is the scale parameter. BayesB introduces variable selection with a point mass at zero with probability π and heavy-tailed distribution with probability 1-π. BayesC uses a common variance for non-zero effects rather than marker-specific variances. BayesCπ estimates π from the data rather than fixing it a priori.
Implementation reuses infrastructure across Bayesian methods with modular components for prior specification, efficient samplers for variance components shared across methods, convergence diagnostics applied uniformly, and result storage formats enabling downstream analysis tools to work with any Bayesian method outputs. Benchmarks comparing these methods on simulated and real data guide users toward appropriate method selection based on genetic architecture, with BayesR and BayesRC generally superior for polygenic traits but computationally intensive, and simpler methods like BayesB adequate when computational resources are limited.
C. Deep Learning Architectures for Genomic Prediction
DeepGBLUP Hybrid Framework represents the state-of-the-art integration of deep learning with quantitative genetics. The architecture consists of locally-connected layers where each genomic locus receives distinct weight parameters rather than shared convolutional filters, respecting biological reality that different genomic regions have fundamentally different effects. The layer structure progresses through LCL^5 with 5 neurons per locus, LCL^3 with 3 neurons per locus reducing dimensionality while preserving positional specificity, followed by layer normalization stabilizing training dynamics, GELU activation providing smooth non-linearity, fully-connected layers with 128 and 64 neurons extracting global patterns, and final linear output predicting initial genomic value.
The GBLUP integration component computes the additive genomic relationship matrix G_A = ZZ' / (2Σp(1-p)), dominance relationship matrix G_D capturing dominance effects through appropriate genotype coding, epistatic relationship matrices G_E modeling specific interaction patterns such as all two-way SNP interactions or selected epistatic terms, and combines these through GV_total = GV_DL + a'G_A a + d'G_D d + e'G_E e where coefficients a, d, e are estimated through GBLUP and GV_DL comes from the neural network.
Training optimization employs joint loss functions L = MSE(y, GV_total) + λ₁||θ_DL||₂ + λ₂||a||₂ where θ_DL represents neural network parameters, a represents GBLUP coefficients, and regularization terms prevent overfitting. The alternating optimization strategy updates neural network parameters for fixed GBLUP coefficients using Adam optimizer with learning rate 0.0001-0.001 and 20-50 epochs, then updates GBLUP coefficients for fixed neural network through REML or Bayesian estimation, and iterates until convergence typically 3-5 cycles. Data augmentation techniques include random SNP masking simulating missing data, random window shifting when using sequence context, and bootstrap resampling for ensemble predictions.
Implementation achieves computational efficiency through batch processing with batch size 64-256 balancing memory and stochastic gradient noise, mixed precision training with BFloat16 forward pass and Float32 gradients, gradient accumulation simulating larger batches when memory-limited, and checkpointing enabling training interruption and resumption. Validation strategies employ forward validation splitting by birth year to avoid information leakage, cross-population validation testing on related breeds, and comparison baselines including GBLUP, BayesR, and standard neural networks without GBLUP integration.
Benchmarks on Korean native cattle demonstrate consistent superiority across traits: carcass weight accuracy 0.412 deepGBLUP versus 0.387 GBLUP representing 6.5% improvement, eye muscle area 0.368 versus 0.345 for 6.7% gain, backfat thickness 0.421 versus 0.398 showing 5.8% advantage, and marbling score 0.389 versus 0.365 achieving 6.6% enhancement. Performance holds across dataset sizes from 1,000 to 10,000 animals with relative improvements actually increasing for smaller training sets where traditional methods struggle, demonstrating the hybrid architecture's ability to leverage both relationship information and learned patterns.
Convolutional Neural Networks for Genomic Selection process SNP data as one-dimensional sequences. The input encoding represents genotypes as 0, 1, 2 for additive effects or as two-channel binary encoding 00, 01, 10, 11 capturing dominance. The convolutional layer structure applies 1D convolutions with kernel sizes 3-10 capturing local linkage disequilibrium patterns, uses multiple filter sizes in parallel (3, 5, 7, 9) extracting multi-scale features, employs 32-128 filters per layer learning diverse patterns, applies ReLU activation introducing non-linearity, implements batch normalization stabilizing training and enabling higher learning rates, and uses max pooling reducing dimensionality while preserving important features.
Deep architectures stack 2-5 convolutional blocks with increasing filter counts (32 → 64 → 128) learning hierarchical features, implement residual connections enabling gradient flow in very deep networks, use global average pooling reducing each feature map to a single value, and connect to fully-connected layers for final prediction. Spatial dropout applied after convolutional layers with probability 0.2-0.4 prevents overfitting by randomly dropping entire feature maps, while L2 regularization with coefficient 1e-4 to 1e-3 constrains weight magnitudes.
The stacked kinship CNN innovation represents genomic relationships as 3D tensors with dimensions samples × samples × relationship_types, where relationship types span additive kinship at different MAF thresholds, dominance kinship matrices, and epistatic terms. The 2D slice per sample extracts a samples × relationship_types matrix fed to CNNs, enabling the network to learn how different relationship types predict phenotypes. This approach improved RMSE by 1-12% over GBLUP for traits with substantial non-additive variance while maintaining computational tractability.
Transformer Architectures for Long-Range Genomic Interactions employ multi-head self-attention mechanisms computing attention scores Attention(Q,K,V) = softmax(QK'/√d_k)V where queries Q, keys K, and values V derive from input embeddings, d_k is the key dimension, and softmax normalization ensures attention weights sum to one. Multiple attention heads capture different types of relationships with head_i computing attention independently using separate parameter matrices W^Q_i, W^K_i, W^V_i, concatenating head outputs, and projecting through W^O to combine information.
Positional encoding injects sequence position information using sinusoidal functions PE(pos,2i) = sin(pos/10000^(2i/d_model)) and PE(pos,2i+1) = cos(pos/10000^(2i/d_model)) where pos is position, i is dimension, and d_model is model dimensionality. For genomic data, absolute positions correspond to base pair coordinates, while relative position encoding represents distances between SNPs accounting for variable spacing.
Layer structure stacks transformer blocks each containing multi-head self-attention, layer normalization, feed-forward networks with two linear layers and GELU activation, and residual connections. The computational bottleneck of O(n²) attention complexity for sequence length n necessitates optimization strategies including sparse attention patterns restricting attention to local windows and global tokens, linear attention approximations using kernel methods and low-rank factorizations, and window-based processing analyzing genomic regions independently then aggregating.
Fine-tuning pre-trained genomic foundation models like Nucleotide Transformer requires extracting sequence context around candidate variants typically 1kb-10kb windows, tokenizing using k-mer encoding (k=3-6) or byte-pair encoding, feeding through frozen transformer encoder layers, adding task-specific heads such as linear regression for breeding values or multi-layer perceptron for disease classification, training only the head initially with learning rate 1e-3 for 10-20 epochs, then fine-tuning full model with lower learning rate 1e-5 for 50-100 epochs. Data efficiency gains achieve comparable accuracy with 10-20× less labeled data than training from scratch, critical for livestock species with limited genotyped populations.
Variational Autoencoders for Genotype Imputation learn compressed representations of genotypes enabling high-accuracy imputation. The encoder network maps high-dimensional genotypes X through layers [input → 2000 → 200] where 200 is the latent dimension, outputs mean μ and log-variance log(σ²) for the latent distribution, samples latent variable z using the reparameterization trick z = μ + σ ⊙ ε where ε ~ N(0,I) and ⊙ is element-wise product enabling backpropagation. The decoder network reconstructs genotypes from latent codes through layers [200 → 2000 → output], uses sigmoid activation for binary genotype probabilities, and outputs the reconstructed genotype probabilities.
Training optimizes the evidence lower bound ELBO = E_q[log p(X|z)] - KL(q(z|X)||p(z)) where the first term is reconstruction loss measured as binary cross-entropy between input and output genotypes, and the second term is Kullback-Leibler divergence between the learned latent distribution and the prior normal distribution. The β-VAE variant weights the KL term with coefficient β controlling the trade-off between reconstruction quality and latent space regularization, with β=1 being standard VAE and β>1 encouraging more structured latent spaces though with potential reconstruction quality sacrifice.
Implementation details include training on reference panels with high-density genotypes for 2,000-5,000 epochs using Adam optimizer with learning rate 0.001, batch size 128-256 for stable gradients, latent dimension 200-400 optimized through validation experiments with dimensions too small (50) performing poorly and too large (800) offering no benefit, shift correction for MNAR scenarios adding parameter λ to the learned distribution compensating for systematic biases, and inference computing p(missing | observed) = ∫ p(missing | z) p(z | observed) dz through Monte Carlo sampling. Performance achieves >95% accuracy for SNPs with MAF>5% while maintaining 140-615× speedup over SVD at inference, enabling real-time genomic evaluation in breeding programs.
D. Multi-Omics Integration Methods
Cross-Attention Fusion Architecture integrates heterogeneous omics data through learned attention mechanisms. Separate encoders process each modality with SNP encoder using 1D CNN extracting local genomic patterns, RNA-seq encoder employing VAE reducing tens of thousands of gene expression measurements to 100-500 dimensions, metabolite encoder using fully-connected networks with dropout, and environmental encoder processing temporal sequences through LSTM layers. The encoded representations feed into cross-attention layers where queries from one modality attend to keys and values from another, enabling the model to learn which genomic variants influence which transcripts, which metabolites associate with which expression patterns, and how environmental factors moderate genetic effects.
The attention computation for modality i attending to modality j calculates Attention_ij(Q_i, K_j, V_j) = softmax(Q_iK_j'/√d_k)V_j where Q_i = W^Q_i h_i are queries from modality i's representation h_i, K_j = W^K_j h_j and V_j = W^V_j h_j are keys and values from modality j's representation, and W matrices are learned parameters. Multi-head attention computes this for each head and concatenates results, while gating mechanisms control modality influence through α_i = sigmoid(W_g[h_i; context]) determining the weight for modality i based on its representation and task context.
Integration strategies include all-to-all cross-attention where every modality attends to every other, hierarchical fusion organizing modalities by biological hierarchy (genomics → transcriptomics → metabolomics → phenotypes) with attention flowing through levels, and graph-based integration representing molecules as nodes and biological relationships as edges, then applying graph attention networks. The fusion operation aggregates attended representations through weighted sum h_fused = Σ_i α_i h_i with learned weights, concatenation [h_1; h_2; ...; h_n] preserving all information, or attention-based pooling learning to attend to most relevant modality features.
Training employs multi-task learning optimizing prediction of multiple phenotypes simultaneously with loss L = Σ_t w_t L_t(y_t, ŷ_t) + λ_reg Σ_i ||θ_i||₂ where t indexes traits, w_t are trait-specific weights, and θ_i are encoder parameters. Data augmentation includes random modality dropout simulating missing omics measurements, noise injection to each modality independently, and permutation of non-causal features maintaining associations while providing contrastive examples.
Validation strategies assess improvements over single-omics baselines, conduct ablation studies removing one modality at a time to quantify individual contributions, verify that attention patterns align with known biological relationships such as eQTLs where genomic variants influence expression, and test generalization through cross-population prediction. Benchmarks demonstrate 10-20% accuracy improvements for complex traits when integrating genomics with transcriptomics, metabolomics, and environmental data compared to genomics alone, with gains larger for traits influenced by multiple biological levels and environmental interactions.

III. Computational Optimization and Performance Engineering
A. Memory Management Strategies for Genomic-Scale Data
Genomic data scale presents formidable memory challenges with 100,000 individuals genotyped at 10 million markers requiring approximately 1 terabyte uncompressed. Systematic optimization strategies reduce requirements by 10-20× while maintaining computational efficiency. Two-bit encoding for biallelic SNPs stores genotypes 00, 01, 10, 11 representing homozygous reference, heterozygous, homozygous alternate, and missing using only two bits rather than eight bits per genotype, reducing storage from 1TB to 250GB, implemented through bitpacking where 32 genotypes occupy one UInt64 integer, extraction via bitshift and mask operations, and vectorized operations processing 32 genotypes simultaneously through SIMD instructions.
Sparse matrix representations leverage the sparsity inherent in genomic data with imputed dosages often containing >90% zeros, dominance encoding with homozygotes as zero and heterozygotes as one creating natural sparsity, and identity-by-state matrices where most pairs are unrelated. Implementation uses CSR format storing non-zero values with row pointers and column indices, CSC format preferred for column-oriented operations, and cuSPARSE for GPU-accelerated sparse operations achieving 10-100× memory reduction while maintaining computational performance within 20% of dense operations.
Memory-mapped arrays enable out-of-core computation exceeding RAM capacity through Mmap.Array mapping files directly to memory, operating system paging bringing needed sections into RAM transparently, column-major access patterns maximizing cache hits and minimizing page faults, and chunked processing analyzing 10,000-SNP windows sequentially. Implementation considerations include pre-allocating files to exact sizes avoiding costly growth operations, using binary formats for fast deserialization versus text formats, aligning data structures to page boundaries enabling efficient paging, and monitoring page faults with system tools identifying performance bottlenecks.
Block-diagonal relationship matrices exploit population structure reducing complexity from O(N²) to O(Σn²_i) where N is total population and n_i are subpopulation sizes. Implementation identifies clusters through principal components analysis or breed assignment, computes separate relationship matrices per cluster each being much smaller, stores in block-diagonal format with CSR encoding, and solves mixed model equations exploiting block structure through block-wise operations. This strategy proves particularly effective for multi-breed populations and international evaluations where between-breed relationships are minimal.
Lazy evaluation and views defer computation until actually needed and avoid unnecessary copies. Julia's @views macro creates views rather than copies when slicing arrays, broadcast fusion combines multiple element-wise operations into single-pass kernels eliminating intermediate allocations, generator expressions compute values on-demand without materializing arrays, and iterator protocols enable processing of infinite or very large sequences without loading entirely into memory. Strategic application throughout the codebase accumulates substantial memory savings.
B. GPU Acceleration Architecture and Kernels
GPU acceleration delivers transformative 50-400× speedups for genomic computations through massive parallelism exploiting thousands of cores operating concurrently. Genomic relationship matrix computation implements as G = ZZ' / (2Σp(1-p)) where Z is centered and scaled genotypes. The blocked algorithm partitions markers into blocks of 2,000-10,000 fitting in GPU memory, computes partial products for each block with CUDA kernel assigning each thread to compute one element of the G submatrix, accumulates partial results reducing memory transfers, and normalizes by the scaling factor. Kernel optimization strategies include coalesced memory access ensuring threads in a warp access contiguous memory addresses maximizing bandwidth, shared memory utilization storing frequently accessed data in fast on-chip memory, occupancy optimization balancing thread block size against register and shared memory usage, and loop unrolling reducing branch overhead.
Performance analysis demonstrates computation time scaling linearly with marker count and quadratically with sample count, with 100,000 individuals and 1 million markers completing in approximately 30 minutes on A100 GPU compared to 200 hours on 64-core CPU, memory transfer overhead minimized by performing multiple operations on GPU before transferring results back, and mixed precision using Float32 operations with Float64 accumulation maintaining accuracy while doubling throughput on modern GPUs. The implementation includes error checking after each kernel launch, memory pool management reducing allocation overhead, and streaming for datasets exceeding GPU memory capacity.
Preconditioned Conjugate Gradient solver for mixed model equations implements through CUDA kernels for sparse matrix-vector multiplication assigning each thread to compute one output element, vector operations including dot products using parallel reduction patterns and AXPY operations performing y = ax + y in parallel, preconditioner application using diagonal or block-Jacobi preconditioners stored in fast memory, and convergence checking on GPU avoiding transfers. Numerical stability considerations include compensated summation for dot products reducing round-off error accumulation, residual correction recomputing exact residuals periodically to prevent drift, and adaptive precision switching to Float64 when Float32 convergence stalls.
Performance benchmarks achieve 7-402× speedup depending on problem size and sparsity, with optimal performance for medium-sized problems (10,000-50,000 individuals) where GPU occupancy is high but memory fits comfortably, communication overhead remaining under 5% of total time when the matrix multiplication dominates, and convergence rates matching CPU implementations confirming numerical equivalence. Implementation includes automatic tuning of thread block sizes based on GPU architecture, heuristic selection between direct and iterative methods based on problem characteristics, and fallback to CPU for tiny problems where GPU launch overhead exceeds computation time.
MCMC sampling kernels accelerate Bayesian methods through parallel sampling of independent marker effects, batch updating residuals for groups of markers simultaneously, parallel variance component updates when using conjugate priors, and chain diagnostics computed on GPU. The residual update kernel r = r + X_j(β_j^old - β_j^new) processes markers in batches of 1,000-10,000 with each thread handling one individual's residual update across all markers in the batch, shared memory caching the genotype matrix block, and atomic operations ensuring correct updates when multiple threads modify the same residual. Memory coalescing optimizes by transposing genotype matrix from markers-by-individuals to individuals-by-markers layout enabling coalesced access patterns.
Multi-GPU scaling distributes data across devices through model parallelism partitioning the marker set across GPUs each handling a subset, data parallelism replicating the model and partitioning individuals across GPUs, hybrid strategies using both model and data parallelism depending on problem characteristics, and gradient synchronization with NCCL enabling efficient multi-GPU communication. Load balancing ensures equal work distribution accounting for heterogeneous GPU capabilities, dynamic scheduling adjusting work distribution during runtime, and fault tolerance through checkpointing enabling recovery from GPU failures in long-running jobs.
C. Numerical Stability and Accuracy Considerations
Genomic computations pose numerical challenges from extreme condition numbers in relationship matrices arising from family structures, variance components spanning many orders of magnitude in mixed models, and accumulation of round-off errors in iterative algorithms. Matrix condition number monitoring computes estimates without full eigendecomposition using iterative methods, triggers warnings when condition exceeds 1e10 indicating near-singularity, suggests remedies including adding small diagonal perturbation λI to improve conditioning, and removes redundant individuals or markers when possible.
Variance component estimation employs stable algorithms avoiding numerical overflow or underflow through log-space computation calculating log(σ²) rather than σ² directly preventing underflow near zero, constrained optimization enforcing positivity through parameterization σ² = exp(θ) guaranteeing positive variance estimates, and adaptive step sizes in gradient-based methods reducing steps when updates cause numerical issues. REML estimation uses efficient algorithms including average information REML computing expected information matrix avoiding second derivatives, expectation-maximization algorithm guaranteeing monotonic likelihood improvement, and Newton-Raphson with line search ensuring global convergence.
Iterative solver convergence monitors through residual norms tracking ||b - Ax|| where x is current solution, relative residuals considering ||b - Ax|| / ||b|| for scale-invariant assessment, and Gelman-Rubin statistics for MCMC assessing between-chain versus within-chain variance. Preconditioning strategies include diagonal scaling normalizing by diagonal elements of coefficient matrix, incomplete Cholesky factorization providing approximate factorization cheaply, and multigrid methods for structured problems using hierarchy of problem resolutions.
Numerical precision management defaults to Float32 for most genomic operations providing sufficient precision while doubling throughput, uses Float64 for REML likelihood evaluation and variance component updates where higher precision is critical, implements mixed precision training with BFloat16 forward pass and Float32 backward pass and accumulation, and provides Float64 fallback when Float32 produces unstable results detectable through diverging iterations or invalid predictions.
Reproducibility measures ensure consistent results across runs through fixed random seeds for MCMC initialization and data splitting, deterministic GPU operations setting CUDA flags to disable non-deterministic algorithms trading minor performance for reproducibility, checkpoint validation storing intermediate results and comparing on resumption, and regression testing maintaining reference results from validated previous versions.

"""

    genotype_file::String,
    phenotype_file::String;
    trait::String = "trait1",
    use_gpu::Bool = true,
    maf_threshold::Float64 = 0.01,
    missing_threshold::Float64 = 0.10,
    n_folds::Int = 5,
    convergence_tol::Float64 = 1e-6,
    max_iterations::Int = 1000
)
    # Step 1: Load and validate data
    println("Loading genotype data from $genotype_file...")
    genotypes = read_genotypes(genotype_file)
    println("  Loaded $(size(genotypes, 1)) individuals with $(size(genotypes, 2)) markers")
    
    println("Loading phenotype data from $phenotype_file...")
    phenotypes = read_phenotypes(phenotype_file, trait_names=[trait])
    println("  Loaded $(length(phenotypes)) phenotype records")
    
    # Validate that sample IDs match between genotypes and phenotypes
    common_ids = intersect(get_sample_ids(genotypes), get_sample_ids(phenotypes))
    println("  Found $(length(common_ids)) individuals with both genotype and phenotype data")
    
    # Subset to common individuals
    genotypes = subset_samples(genotypes, common_ids)
    phenotypes = subset_samples(phenotypes, common_ids)

    println("\nApplying quality control filters...")
    qc_pipeline = QCPipeline([
        MissingRateFilter(sample_threshold=missing_threshold, marker_threshold=missing_threshold),
        MAFFilter(min_maf=maf_threshold),
        HWEFilter(pvalue_threshold=1e-6)
    ])
    
    genotypes_qc, qc_report = apply_qc(genotypes, qc_pipeline)
    println(qc_report)
    println("  Retained $(size(genotypes_qc, 1)) samples and $(size(genotypes_qc, 2)) markers after QC")
    
    # Step 3: Compute genomic relationship matrix
    println("\nComputing genomic relationship matrix...")
    if use_gpu && CUDA.functional()
        println("  Using GPU acceleration ($(CUDA.device()))")
        G = compute_grm(genotypes_qc, method=:VanRaden, backend=:gpu)
        println("  GRM computation completed on GPU")
    else
        println("  Using CPU implementation")
        G = compute_grm(genotypes_qc, method=:VanRaden, backend=:cpu)
        println("  GRM computation completed on CPU")
    end
    
    # Validate GRM properties
    G_diag_mean = mean(diag(G))
    G_offdiag_mean = mean(G[i,j] for i in 1:size(G,1), j in 1:size(G,2) if i != j)
    println("  GRM diagonal mean: $(round(G_diag_mean, digits=3)) (expect ~1.0)")
    println("  GRM off-diagonal mean: $(round(G_offdiag_mean, digits=3)) (expect ~0.0)")

    println("\nFitting GBLUP model...")
    y = get_phenotypes(phenotypes, trait)
    
    # Estimate variance components using REML
    println("  Estimating variance components via AI-REML...")
    var_components = estimate_variance_components(
        G, y,
        method=:AIREML,
        tolerance=1e-6,
        max_iterations=100
    )
    
    σ²_g = var_components.genetic_variance
    σ²_e = var_components.residual_variance
    h² = σ²_g / (σ²_g + σ²_e)
    
    println("  Genetic variance (σ²_g): $(round(σ²_g, digits=4))")
    println("  Residual variance (σ²_e): $(round(σ²_e, digits=4))")
    println("  Heritability (h²): $(round(h², digits=3))")
    
    # Solve mixed model equations using PCG
    println("  Solving mixed model equations via PCG...")
    λ = σ²_e / σ²_g
    
    gebvs, solver_stats = solve_gblup(
        G, y, λ,
        method=:pcg,
        tolerance=convergence_tol,
        max_iterations=max_iterations,
        preconditioner=:diagonal,
        use_gpu=use_gpu
    )
    
    println("  Solver converged in $(solver_stats.iterations) iterations")
    println("  Final residual norm: $(round(solver_stats.residual_norm, digits=8))")

    cv_results = cross_validate(
        genotypes_qc, phenotypes, trait,
        model_type=:GBLUP,
        n_folds=n_folds,
        var_components=var_components,
        use_gpu=use_gpu
    )
    
    println("  Cross-validation accuracy (correlation): $(round(cv_results.correlation, digits=3))")
    println("  RMSE: $(round(cv_results.rmse, digits=4))")
    println("  Bias (regression slope): $(round(cv_results.bias, digits=3)) (expect ~1.0)")

        var_components = var_components,
        heritability = h²,
        grm = G,
        cv_results = cv_results,
        qc_report = qc_report,
        solver_stats = solver_stats,
        n_individuals = length(gebvs),
        n_markers = size(genotypes_qc, 2)

    println("\n" * "="^60)
    println("GBLUP Analysis Completed Successfully")
    println("="^60)

    println("  Markers: $(results.n_markers)")
    println("  Heritability: $(round(results.heritability, digits=3))")
    println("  CV Accuracy: $(round(cv_results.correlation, digits=3))")
    println("\nUse `save_results(results, \"output_dir\")` to export results")
    println("Use `plot_results(results)` to generate visualizations")
    
    return results
end


"""
    compute_grm(genotypes; method=:VanRaden, backend=:auto)

Compute genomic relationship matrix from SNP genotype data.

The genomic relationship matrix (GRM) captures genetic similarities between
individuals based on molecular markers. Two primary methods are implemented:

1. VanRaden (2008): G = ZZ' / (2∑pᵢ(1-pᵢ))
   - Standard method used in most genomic selection applications
   - Z is centered and scaled genotype matrix
   - pᵢ is allele frequency at marker i

2. Astle & Balding (2009): Alternative scaling
   - Adjusts for allele frequency distribution
   - More robust with ascertainment bias

# Arguments
- `genotypes::AbstractGenotypeData`: Genotype matrix (individuals × markers)
  Coding: 0 = homozygous reference, 1 = heterozygous, 2 = homozygous alternate

# Keyword Arguments
- `method::Symbol = :VanRaden`: Scaling method (:VanRaden or :AstalBalding)
- `backend::Symbol = :auto`: Computation backend (:auto, :cpu, or :gpu)
  - :auto automatically selects GPU if available and problem size > 5000 individuals
- `center::Bool = true`: Center genotypes by subtracting 2p
- `scale::Bool = true`: Scale genotypes by dividing by √(2p(1-p))
- `blocksize::Int = 5000`: Block size for blocked matrix multiplication (GPU only)

# Returns
- `Matrix{Float64}`: Symmetric n×n genomic relationship matrix where n is number of individuals

# Implementation Notes
- CPU implementation uses optimized BLAS for matrix multiplication
- GPU implementation uses blocked algorithm to manage memory efficiently
- Mixed precision (Float32 operations, Float64 accumulation) for GPU
- Returns dense matrix; consider sparse storage for large populations with substructure

# Examples
```julia
# Basic usage with automatic backend selection
genotypes = read_genotypes("data.vcf")
G = compute_grm(genotypes)

# Force GPU computation with custom block size
G_gpu = compute_grm(genotypes, backend=:gpu, blocksize=10000)

# Use alternative scaling method
G_ab = compute_grm(genotypes, method=:AstalBalding)

# Compute on subset of individuals
genotypes_subset = genotypes[1:1000, :]
G_subset = compute_grm(genotypes_subset)
```

# Performance
- CPU: O(n²m) time, O(nm + n²) memory
- GPU: 50-200× speedup for n > 10,000
- Typical timing (NVIDIA A100): 100K individuals, 50K markers → 30 minutes

# References
- VanRaden PM (2008) J Dairy Sci 91:4414-4423
- Astle & Balding (2009) PLoS Genet 5(2):e1000365

# See Also
- [`compute_sparse_grm`](@ref): Sparse GRM for structured populations
- [`compute_dominance_relationship`](@ref): Dominance relationship matrix
"""
function compute_grm(
    genotypes::AbstractGenotypeData;
    method::Symbol = :VanRaden,
    backend::Symbol = :auto,
    center::Bool = true,
    scale::Bool = true,
    blocksize::Int = 5000
)
    n_individuals, n_markers = size(genotypes)
    
    # Automatic backend selection
    if backend == :auto
        backend = (CUDA.functional() && n_individuals > 5000) ? :gpu : :cpu
    end
    
    # Compute allele frequencies
    p = compute_allele_frequencies(genotypes)
    
    # Center and scale genotype matrix to form Z
    Z = center_and_scale_genotypes(genotypes, p, center=center, scale=scale)
    
    # Compute scaling factor based on method
    if method == :VanRaden
        scaling_factor = 2.0 * sum(p .* (1.0 .- p))
    elseif method == :AstalBalding
        scaling_factor = n_markers  # Simplified; actual formula more complex
    else
        throw(ArgumentError("Unknown method: $method. Use :VanRaden or :AstalBalding"))
    end
    
    # Compute G = ZZ' / scaling_factor
    if backend == :gpu
        G = compute_grm_gpu(Z, scaling_factor, blocksize)
    else
        G = compute_grm_cpu(Z, scaling_factor)
    end
    
    return G
end

# Internal function for CPU computation
function compute_grm_cpu(Z::Matrix{Float64}, scaling_factor::Float64)
    # Use optimized BLAS matrix multiplication
    G = (Z * Z') ./ scaling_factor
    return G
end

# Internal function for GPU computation
function compute_grm_gpu(Z::Matrix{Float64}, scaling_factor::Float64, blocksize::Int)
    n = size(Z, 1)
    m = size(Z, 2)
    
    # Allocate result on GPU
    G = CUDA.zeros(Float32, n, n)
    
    # Process markers in blocks to fit GPU memory
    for block_start in 1:blocksize:m
        block_end = min(block_start + blocksize - 1, m)
        
        # Transfer block to GPU
        Z_block = CuArray{Float32}(Z[:, block_start:block_end])
        
        # Accumulate partial product G += Z_block * Z_block'
        CUDA.@sync G .+= Z_block * Z_block'
        
        # Free GPU memory
        CUDA.unsafe_free!(Z_block)
    end
    
    # Scale and transfer result to CPU
    G .= G ./ Float32(scaling_factor)
    G_cpu = Array(G)
    
    # Ensure symmetry (correct for any numerical artifacts)
    G_cpu = (G_cpu + G_cpu') / 2.0
    
    return G_cpu
end

"""
    train_deepgblup(genotypes, phenotypes, trait; kwargs...)

Train deepGBLUP hybrid model combining neural networks with quantitative genetics.

DeepGBLUP integrates locally-connected neural networks (capturing non-additive
genetic effects) with traditional GBLUP (modeling additive relationships). This
hybrid approach consistently outperforms pure neural networks or GBLUP alone.

Architecture:
1. Locally-Connected Layers: Each genomic locus has distinct weights
2. Fully-Connected Layers: Extract global patterns
3. GBLUP Component: Additive breeding values via relationship matrices
4. Joint Prediction: Sum of neural network and GBLUP outputs

# Arguments
- `genotypes::AbstractGenotypeData`: Genotype matrix (individuals × markers)
- `phenotypes::PhenotypeData`: Phenotype data with trait values
- `trait::String`: Name of trait to predict

# Keyword Arguments

- `fc_neurons::Vector{Int} = [128, 64]`: Neurons in fully-connected layers

- `batch_size::Int = 256`: Batch size for mini-batch gradient descent
- `n_epochs::Int = 100`: Maximum number of training epochs
- `early_stopping_patience::Int = 20`: Stop if no improvement for this many epochs
- `validation_split::Float64 = 0.15`: Fraction of data for validation
- `use_gpu::Bool = true`: Use GPU acceleration if available

function train_deepgblup(

    y_mean, y_std = mean(y), std(y)
    y_scaled = (y .- y_mean) ./ y_std

    n_samples = length(y)
    n_val = round(Int, n_samples * validation_split)
    indices = randperm(rng, n_samples)

    val_indices = indices[end-n_val+1:end]

    y_train = y_scaled[train_indices]
    X_val = genotypes[val_indices, :]
    y_val = y_scaled[val_indices]
    
    println("Training set: $(length(train_indices)) samples")
    println("Validation set: $(length(val_indices)) samples")

    n_markers = size(genotypes, 2)

        n_markers,
        lcl_neurons,
        fc_neurons
    )

        ps = ps |> gpu
        st = st |> gpu
        X_train_device = CuArray(Float32.(X_train))
        y_train_device = CuArray(y_train)
        X_val_device = CuArray(Float32.(X_val))
        y_val_device = CuArray(y_val)
        println("Using GPU: $(CUDA.device())")

        X_train_device = Float32.(X_train)
        y_train_device = y_train
        X_val_device = Float32.(X_val)
        y_val_device = y_val
        println("Using CPU")
    end

    println("\nInitializing GBLUP component...")
    G_train = compute_grm(X_train, backend=:cpu)  # GRM for training set
    σ²_g, σ²_e = estimate_variance_components_fast(G_train, y_train)
    λ = σ²_e / σ²_g
    a = solve_gblup(G_train, y_train, λ, method=:pcg).breeding_values
    println("  Initial GBLUP heritability: $(round(σ²_g/(σ²_g+σ²_e), digits=3))")
    
    # Initialize optimizer with learning rate scheduling
    opt_state = Optimisers.setup(
        Optimisers.Adam(learning_rate),
        ps
    )
    
    # Training loop with early stopping
    best_val_loss = Inf
    patience_counter = 0
    training_history = Dict(
        "train_loss" => Float64[],
        "val_loss" => Float64[],
        "val_correlation" => Float64[]
    )
    
    println("\nStarting training...")
    println("="^60)
    
    for epoch in 1:n_epochs
        # Mini-batch training
        epoch_train_loss = 0.0
        n_batches = 0
        
        # Shuffle training data
        shuffle_indices = randperm(rng, length(train_indices))
        
        for batch_start in 1:batch_size:length(train_indices)

            batch_indices = shuffle_indices[batch_start:batch_end]

            a_batch = a[batch_indices]

                # Neural network prediction
                y_pred_nn, _ = model(X_batch, p, st)
                
                # Combine with GBLUP
                y_pred_total = y_pred_nn .+ a_batch
                
                # MSE loss
                mse_loss(y_pred_total, y_batch)
            end
            
            # Backward pass
            grads = back(one(loss_val))[1]
            
            # Update parameters
            opt_state, ps = Optimisers.update(opt_state, ps, grads)
            
            epoch_train_loss += loss_val
            n_batches += 1
        end
        
        epoch_train_loss /= n_batches
        
        # Validation evaluation
        y_pred_val_nn, _ = model(X_val_device, ps, st)
        
        # Compute GBLUP predictions for validation set
        # (requires computing relationships between val and train sets)
        G_val_train = compute_cross_grm(X_val, X_train)
        a_val = G_val_train * (G_train \ a)  # Simplified; actual computation more involved
        
        y_pred_val_total = y_pred_val_nn .+ a_val
        val_loss = mean((y_pred_val_total .- y_val_device).^2)
        val_correlation = cor(Array(y_pred_val_total), Array(y_val_device))
        
        # Store history
        push!(training_history["train_loss"], epoch_train_loss)
        push!(training_history["val_loss"], val_loss)
        push!(training_history["val_correlation"], val_correlation)
        
        # Update GBLUP component periodically
        if epoch % gblup_update_frequency == 0
            println("  Updating GBLUP component...")
            # Extract residuals from neural network
            y_pred_nn_train, _ = model(X_train_device, ps, st)
            residuals = y_train_device .- y_pred_nn_train
            
            # Re-estimate GBLUP on residuals
            σ²_g, σ²_e = estimate_variance_components_fast(G_train, Array(residuals))
            λ = σ²_e / σ²_g
            a = solve_gblup(G_train, Array(residuals), λ, method=:pcg).breeding_values
        end
        
        # Print progress
        if epoch % 5 == 0 || epoch == 1
            println("Epoch $epoch/$n_epochs")
            println("  Train Loss: $(round(epoch_train_loss, digits=5))")
            println("  Val Loss: $(round(val_loss, digits=5))")
            println("  Val Correlation: $(round(val_correlation, digits=4))")
        end
        
        # Early stopping check
        if val_loss < best_val_loss
            best_val_loss = val_loss
            patience_counter = 0
            # Save best parameters
            best_ps = ps
        else
            patience_counter += 1
            if patience_counter >= early_stopping_patience
                println("\nEarly stopping triggered at epoch $epoch")
                ps = best_ps
                break
            end
        end
    end
    
    println("="^60)
    println("Training completed!")
    println("Best validation loss: $(round(best_val_loss, digits=5))")
    println("Best validation correlation: $(round(maximum(training_history["val_correlation"]), digits=4))")
    
    # Create model object
    trained_model = DeepGBLUPModel(
        neural_network = (model=model, params=ps, state=st),
        gblup_coefficients = a,
        grm = G_train,
        variance_components = (σ²_g=σ²_g, σ²_e=σ²_e),
        standardization = (mean=y_mean, std=y_std),
        training_history = training_history,
        n_markers = n_markers
    )
    
    return trained_model
end

"""
    build_deepgblup_architecture(n_markers, lcl_neurons, fc_neurons)

Construct deepGBLUP neural network architecture using Lux.jl.

Creates a chain of locally-connected layers followed by fully-connected layers.
Locally-connected layers assign distinct weights to each genomic locus, respecting
the biological reality that different genome regions have different effects.

# Arguments
- `n_markers::Int`: Number of genetic markers (input dimensionality)
- `lcl_neurons::Vector{Int}`: Neurons per locus in each locally-connected layer
- `fc_neurons::Vector{Int}`: Neurons in each fully-connected layer

# Returns
- `Lux.Chain`: Neural network model ready for training

# Architecture Details
- Input: Genotype matrix (batch_size × n_markers)
- Locally-Connected Layers: Distinct weights per locus with GELU activation
- Layer Normalization: After each LCL for stable training
- Fully-Connected Layers: Global pattern extraction with dropout
- Output: Single neuron predicting genomic value from neural network component

# Example
```julia
# Create architecture for 50,000 markers
model = build_deepgblup_architecture(
    50000,
    [5, 3],  # Two LCL layers
    [128, 64]  # Two FC layers
)
```
"""
function build_deepgblup_architecture(
    n_markers::Int,
    lcl_neurons::Vector{Int},
    fc_neurons::Vector{Int}
)
    layers = []
    
    # Build locally-connected layers
    input_dim = 1
    for (i, n_neurons) in enumerate(lcl_neurons)
        # Locally-connected layer: separate weight matrix for each locus
        push!(layers, LocallyConnectedLayer(n_markers, input_dim, n_neurons))
        push!(layers, LayerNorm((n_markers, n_neurons,)))
        push!(layers, Lux.gelu)
        input_dim = n_neurons
    end
    
    # Flatten to feed into fully-connected layers
    push!(layers, Lux.FlattenLayer())
    
    # Build fully-connected layers
    fc_input_dim = n_markers * lcl_neurons[end]
    for (i, n_neurons) in enumerate(fc_neurons)
        push!(layers, Dense(fc_input_dim, n_neurons, gelu))
        push!(layers, Dropout(0.3))
        fc_input_dim = n_neurons
    end
    
    # Output layer
    push!(layers, Dense(fc_input_dim, 1))
    
    return Chain(layers...)
end

"""
    train_multiomics_model(genomics, transcriptomics, phenotypes, trait; kwargs...)

Train multi-omics integration model combining genomics and transcriptomics data.

Architecture:

# See Also

"""
function train_multiomics_model(
    genomics::AbstractGenotypeData,
    transcriptomics::ExpressionData,
    phenotypes::PhenotypeData,
    trait::String;
    snp_encoder_config::Union{Dict,Nothing} = nothing,
    expression_encoder_config::Union{Dict,Nothing} = nothing,
    latent_dim::Int = 256,
    n_attention_heads::Int = 8,
    learning_rate::Float64 = 0.0005,
    batch_size::Int = 64,
    n_epochs::Int = 150,
    validation_split::Float64 = 0.2,
    use_gpu::Bool = true
)
    rng = Random.default_rng()
    Random.seed!(rng, 42)
    
    # Extract and validate data
    y = get_phenotypes(phenotypes, trait)
    n_samples = length(y)
    n_snps = size(genomics, 2)
    n_genes = size(transcriptomics, 1)
    
    println("Multi-Omics Data Summary:")
    println("  Samples: $n_samples")
    println("  SNP markers: $n_snps")
    println("  Gene expression features: $n_genes")
    
    # Validate that samples match across modalities
    snp_ids = get_sample_ids(genomics)
    expr_ids = get_sample_ids(transcriptomics)
    pheno_ids = get_sample_ids(phenotypes)
    
    common_ids = intersect(snp_ids, expr_ids, pheno_ids)
    if length(common_ids) < n_samples
        @warn "Only $(length(common_ids)) samples have data across all modalities"
        genomics = subset_samples(genomics, common_ids)
        transcriptomics = subset_samples(transcriptomics, common_ids)
        phenotypes = subset_samples(phenotypes, common_ids)
        y = get_phenotypes(phenotypes, trait)
        n_samples = length(common_ids)
    end
    
    # Preprocess each modality
    println("\nPreprocessing omics data...")
    
    # Genomics: standardize genotypes
    X_snp = standardize_genotypes(genomics)
    println("  Genomics preprocessing complete")
    
    # Transcriptomics: log-transform and normalize
    X_expr = log_transform_and_normalize(transcriptomics)
    println("  Transcriptomics preprocessing complete")
    
    # Standardize phenotypes
    y_mean, y_std = mean(y), std(y)
    y_scaled = (y .- y_mean) ./ y_std
    
    # Train-validation split
    n_val = round(Int, n_samples * validation_split)
    indices = randperm(rng, n_samples)
    train_idx = indices[1:end-n_val]
    val_idx = indices[end-n_val+1:end]
    
    # Build multi-omics architecture
    println("\nBuilding multi-omics fusion architecture...")
    
    # SNP encoder (1D CNN)
    if isnothing(snp_encoder_config)
        snp_encoder = build_snp_encoder(n_snps, latent_dim)
    else
        snp_encoder = build_snp_encoder(n_snps, latent_dim, snp_encoder_config)
    end
    
    # Expression encoder (VAE)
    if isnothing(expression_encoder_config)
        expr_encoder = build_expression_vae(n_genes, latent_dim)
    else
        expr_encoder = build_expression_vae(n_genes, latent_dim, expression_encoder_config)
    end
    
    # Cross-attention fusion layer
    fusion_layer = CrossAttentionFusion(
        latent_dim,
        n_heads = n_attention_heads,
        dropout = 0.2
    )
    
    # Prediction head
    predictor = Chain(
        Dense(latent_dim * 2, 256, gelu),
        Dropout(0.3),
        Dense(256, 128, gelu),
        Dropout(0.3),
        Dense(128, 1)
    )
    
    # Combine into full model
    model = MultiOmicsIntegrationModel(
        snp_encoder = snp_encoder,
        expression_encoder = expr_encoder,
        fusion_layer = fusion_layer,
        predictor = predictor
    )
    
    # Initialize parameters
    ps, st = Lux.setup(rng, model)
    
    # Move to GPU if requested
    if use_gpu && CUDA.functional()
        ps = ps |> gpu
        st = st |> gpu
        device = gpu
        println("Using GPU: $(CUDA.device())")
    else
        device = cpu
        println("Using CPU")
    end
    
    # Prepare data on device
    X_snp_train = X_snp[train_idx, :] |> device
    X_expr_train = X_expr[:, train_idx] |> device
    y_train = y_scaled[train_idx] |> device
    
    X_snp_val = X_snp[val_idx, :] |> device
    X_expr_val = X_expr[:, val_idx] |> device
    y_val = y_scaled[val_idx] |> device
    
    # Initialize optimizer
    opt_state = Optimisers.setup(Optimisers.Adam(learning_rate), ps)
    
    # Training loop
    println("\nStarting training...")
    println("="^60)
    
    best_val_loss = Inf
    patience_counter = 0
    patience = 20
    
    training_history = Dict(
        "train_loss" => Float64[],
        "val_loss" => Float64[],
        "val_correlation" => Float64[]
    )
    
    for epoch in 1:n_epochs
        # Mini-batch training
        epoch_train_loss = 0.0
        n_batches = 0
        
        shuffle_idx = randperm(rng, length(train_idx))
        
        for batch_start in 1:batch_size:length(train_idx)
            batch_end = min(batch_start + batch_size - 1, length(train_idx))
            batch_idx = shuffle_idx[batch_start:batch_end]
            
            # Forward pass with both modalities
            loss_val, back = Zygote.pullback(ps) do p
                # Encode each modality
                snp_repr, st_snp = model.snp_encoder(
                    X_snp_train[batch_idx, :], 
                    p.snp_encoder, 
                    st.snp_encoder
                )
                
                expr_repr, st_expr = model.expression_encoder(
                    X_expr_train[:, batch_idx],
                    p.expression_encoder,
                    st.expression_encoder
                )
                
                # Fuse with cross-attention
                fused_repr, st_fusion = model.fusion_layer(
                    snp_repr,
                    expr_repr,
                    p.fusion_layer,
                    st.fusion_layer
                )
                
                # Predict phenotype
                y_pred, st_pred = model.predictor(
                    fused_repr,
                    p.predictor,
                    st.predictor
                )
                
                # MSE loss
                mean((y_pred .- y_train[batch_idx]).^2)
            end
            
            # Backward pass
            grads = back(one(loss_val))[1]
            opt_state, ps = Optimisers.update(opt_state, ps, grads)
            
            epoch_train_loss += loss_val
            n_batches += 1
        end
        
        epoch_train_loss /= n_batches
        
        # Validation evaluation
        y_pred_val, _ = predict_with_model(
            model, ps, st,
            X_snp_val, X_expr_val
        )
        
        val_loss = mean((y_pred_val .- y_val).^2)
        val_correlation = cor(Array(y_pred_val), Array(y_val))
        
        push!(training_history["train_loss"], epoch_train_loss)
        push!(training_history["val_loss"], val_loss)
        push!(training_history["val_correlation"], val_correlation)
        
        # Print progress
        if epoch % 10 == 0 || epoch == 1
            println("Epoch $epoch/$n_epochs")
            println("  Train Loss: $(round(epoch_train_loss, digits=5))")
            println("  Val Loss: $(round(val_loss, digits=5))")
            println("  Val Correlation: $(round(val_correlation, digits=4))")
        end
        
        # Early stopping
        if val_loss < best_val_loss
            best_val_loss = val_loss
            patience_counter = 0
            best_ps = ps
        else
            patience_counter += 1
            if patience_counter >= patience
                println("\nEarly stopping at epoch $epoch")
                ps = best_ps
                break
            end
        end
    end
    
    println("="^60)
    println("Training completed!")
    println("Best validation correlation: $(round(maximum(training_history["val_correlation"]), digits=4))")
    
    # Create trained model object
    trained_model = TrainedMultiOmicsModel(
        architecture = model,
        parameters = ps,
        state = st,
        standardization = (mean=y_mean, std=y_std),
        training_history = training_history,
        n_samples = n_samples,
        n_snps = n_snps,
        n_genes = n_genes
    )
    
    return trained_model
end

"""
    CrossAttentionFusion

Lux layer implementing cross-attention between omics modalities.

Enables genomics representation to attend to transcriptomics representation,
learning which genomic variants influence which transcripts in a data-driven manner.

# Fields
- `d_model::Int`: Dimensionality of input representations
- `n_heads::Int`: Number of attention heads
- `dropout::Float64`: Dropout probability for regularization

# Forward Pass
Input: Two representations (queries from modality A, keys/values from modality B)
Output: Fused representation combining information from both modalities

# Mathematics
For each attention head h:
  Q_h = LinearQ_h(repr_A)
  K_h = LinearK_h(repr_B)
  V_h = LinearV_h(repr_B)
  Attention_h = softmax(Q_h K_h' / √d_k) V_h

Concatenate heads and project:
  Output = LinearOut([Attention_1; ...; Attention_H])
"""
struct CrossAttentionFusion{Q,K,V,O} <: Lux.AbstractExplicitLayer
    query_proj::Q
    key_proj::K
    value_proj::V
    output_proj::O
    n_heads::Int
    dropout::Float64
end

function CrossAttentionFusion(d_model::Int; n_heads::Int=8, dropout::Float64=0.1)
    d_head = d_model ÷ n_heads
    
    CrossAttentionFusion(
        Dense(d_model, d_model),  # Query projection
        Dense(d_model, d_model),  # Key projection
        Dense(d_model, d_model),  # Value projection
        Dense(d_model, d_model),  # Output projection
        n_heads,
        dropout
    )
end

function (l::CrossAttentionFusion)(repr_a, repr_b, ps, st)
    # Project to queries, keys, values
    Q, st_q = l.query_proj(repr_a, ps.query_proj, st.query_proj)
    K, st_k = l.key_proj(repr_b, ps.key_proj, st.key_proj)
    V, st_v = l.value_proj(repr_b, ps.value_proj, st.value_proj)
    
    # Multi-head attention
    batch_size, d_model = size(Q)
    d_head = d_model ÷ l.n_heads
    
    # Reshape for multi-head: (batch, d_model) -> (batch, n_heads, d_head)
    Q = reshape(Q, batch_size, l.n_heads, d_head)
    K = reshape(K, batch_size, l.n_heads, d_head)
    V = reshape(V, batch_size, l.n_heads, d_head)
    
    # Compute attention scores
    scores = batched_mul(Q, permutedims(K, (1, 3, 2))) / sqrt(Float32(d_head))
    attention_weights = softmax(scores, dims=3)
    
    # Apply dropout
    if st.training
        attention_weights = dropout_layer(attention_weights, l.dropout)
    end
    
    # Apply attention to values
    attended = batched_mul(attention_weights, V)
    
    # Reshape back: (batch, n_heads, d_head) -> (batch, d_model)
    attended = reshape(attended, batch_size, d_model)
    
    # Final output projection
    output, st_o = l.output_proj(attended, ps.output_proj, st.output_proj)
    
    # Update state
    new_st = (
        query_proj = st_q,
        key_proj = st_k,
        value_proj = st_v,
        output_proj = st_o,
        attention_weights = attention_weights,  # Store for interpretation
        training = st.training
    )
    
    return output, new_st
end

C. Testing Strategy for AI-Generated Code
Implement comprehensive three-tier testing strategy ensuring correctness of AI-generated code. Unit testing validates individual functions in isolation creating test cases covering typical inputs, edge cases including empty arrays and extreme values, error conditions ensuring appropriate exception raising, and numerical accuracy comparing to reference implementations with tight tolerances. Property-based testing uses Hypothesis.jl or similar generating random valid inputs and checking invariants that should always hold. Integration testing verifies component interaction ensuring data flows correctly between modules, modules integrate without conflicts, end-to-end workflows complete successfully, and performance remains acceptable for realistic problem sizes. Use realistic test datasets representative of actual usage. Regression testing prevents performance degradation establishing baseline benchmarks for critical operations, running benchmarks automatically in CI detecting performance regressions, maintaining historical performance data tracking trends over time, and investigating causes when regressions detected. Automated regression detection alerts developers to issues before release.
Test organization and execution structure tests hierarchically with test/unit/ containing per-module test files, test/integration/ for workflow tests, test/performance/ for benchmarks, and test/fixtures/ for test data. Use Test.jl standard library for test framework, BenchmarkTools.jl for performance tests, and Coverage.jl for coverage reporting. CI configuration runs tests automatically on push to repository, all pull requests before merging, scheduled nightly for comprehensive testing, and multiple Julia versions ensuring compatibility. Coverage reporting generates coverage reports highlighting untested code, enforces minimum coverage threshold blocking merges below 85%, and focuses effort on increasing coverage of critical paths. Test documentation includes clear descriptions of what each test validates, comments explaining complex test logic, examples demonstrating test data generation, and maintenance notes for updating tests as code evolves.

E. Performance Optimization Workflow
Systematic approach to optimizing performance after initial implementation establishes baseline by benchmarking initial implementation recording current performance, identifies bottlenecks using profiling tools (@time, @benchmark, @profile) finding slow sections, analyzes computational complexity ensuring algorithmic efficiency, and examines memory allocation patterns finding unnecessary allocations. Document baseline metrics for comparison after optimization. Optimization strategies prioritize high-impact improvements focusing on most expensive operations, applies type stability fixes ensuring consistent return types, reduces allocations using in-place operations and pre-allocation, leverages SIMD and vectorization through broadcasting, exploits parallelism using threads or distributed computing, and considers algorithmic improvements like better data structures or algorithms. Benchmark after each optimization measuring impact.
Verification of correctness after optimization compares results to baseline implementation ensuring no regression, runs comprehensive tests validating accuracy, checks numerical stability examining condition numbers and error accumulation, and validates on diverse datasets including edge cases. Catches performance issues early in development.
